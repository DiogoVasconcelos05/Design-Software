# ADR-001: Adocao de Particionamento de Topo por Dominio

* **Status:** Aceite
* **Data:** 2026-10-10
* **Autor:** Diogo Vasconcelos

## Contexto
O sistema Lisboa Pedala precisa de organizar a estrutura de ficheiros e pacotes na raiz do repositório para suportar o trabalho de uma equipa de desenvolvimento e permitir a futura evolução do sistema. A escolha da estrutura de topo afeta o acoplamento global do código e a facilidade com que ferramentas de IA e humanos navegam no projeto.

## Decisao
Adotar o **Particionamento de Topo por Domínio** na raiz do diretório `src/`, onde cada módulo contém a lógica, contratos e dados do seu respetivo domínio de negócio.

## Consequencias
* **Positivas:**
  * Alinha a estrutura do repositório com o ficheiro `CODEOWNERS`, facilitando a divisão vertical do trabalho.
  * Facilita a transição futura para arquiteturas distribuídas ou microsserviços.
  * Mantém o código relacionado com um determinado caso de uso concentrado no mesmo diretório.
* **Negativas:**
  * Utilitários ou abstrações comuns podem ter de ser duplicados ou colocados num módulo partilhado com regras estritas para evitar acoplamento indevido.

## Alternativas Rejeitadas
* **Particionamento Técnico por Camadas (`presentation`, `business`, `persistence`):** Rejeitado porque espalha o código de uma única funcionalidade por várias pastas, aumentando o acoplamento global e dificultando a manutenção isolada por domínio.
